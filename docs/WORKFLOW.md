# 从材料到可检查的视频

目录：项目接手 · 分镜与资产 · MCP 制作 · 渲染审阅 · 视频生成 · 初剪交接 · 恢复与扩展。

## 1. 接手项目

读取用户目标、已有材料、参考图和拍摄素材。确认这次任务的范围：只搭环境、制作试片、修改某组镜头，还是执行全片。沿用用户已经确认的决定，合理处理常规技术选择。

执行 `doctor --probe`，有项目则执行 `status --project ...`。先阅读输出的缺项与过期状态，不因一个阶段受阻而停止所有工作。没有 Blender 连接时，可以完成材料清单、分镜导入、场景规格和生成交接计划；不能把这部分报告成已在 Blender 完成。

项目建议额外维护一个 `BRIEF.md`，记录创作目标、参考素材用途、画幅、帧率、对白/声音安排、已确认决定和仍有歧义的问题。它属于具体作品，不进入通用规则。

## 2. 保留源材料，建立镜头数据

表格通过 `inspect-input` 明确工作表、表头和列名，再 `import-shots`。相同镜号的两行仍是两个镜头；短镜保留原时长。以实际 fps 换算整数帧，并报告无法整除的量化误差。

文本剧本或图片分镜由 Codex 先理解并整理成逐镜数据。为每个镜头写清楚主体、动作、景别、机位、运动、时长、声音、需要遵守的参考和不能改变的内容。不能把缺失信息伪装成源材料中的明确要求。

将镜头分为适合的制作方式，例如静态机位、移动摄影、人物走位、精确道具接触、复杂模拟、已有实拍。这个分类指导执行方式，不改变分镜内容。制作低成本预演时保留运动、遮挡、接触与空间关系；对最终画面重要的几何关系不能全部交给生成模型猜测。

## 3. 资产与场景复用

给角色、道具、空间和相机稳定 ID。相同角色使用同一组尺寸/外观参考；相同空间跨镜头复用布局。明确单位、地面高度、轴方向、镜头焦距、机位高度、视线目标和动作发生的帧区间。

以参考图建立清晰映射：哪个白模对象对应哪位角色、哪个道具或场景参考。不同镜头可以更换机位和光线，但不无意改变人物比例、服装、关键道具及空间拓扑。

声明式场景适合白模几何体和普通变换动画。已有模型、骨骼、模拟或其他复杂工程通过 MCP 制作，随后使用 `adopt-blend` 接入；保持工程资源齐全，外部贴图/链接资产要随项目管理，不能只交付丢失依赖的文件。

## 4. MCP 中执行制作

先使用当前会话的场景观察工具读取当前文件与对象，再操作。新版工具提供 `get_scene_info`、`execute_blender_code`、`look` 等；具体名称与参数以本次工具列表为准，不假定旧教程中的名称始终存在。

让 Codex 用 `bpy` 创建和修改场景，按需要查看相机图、多个角度或动作帧。每轮修改对应一个明确目的：例如改善构图、修正接触、控制速度、保持轴线或衔接下一镜。结果偏离分镜时直接修正，不能靠文字声称已经符合。

先选能检验主要难点的一小段完成“制作—渲染—审阅—修正”，将确定的资产与参数复用于后续镜头。不要逐镜重建同一个空间或反复生成新的角色身份。

简单参数修改同步回 `scene.json` 再 build。复杂工程在 MCP 保存后 adopt，保留说明和旧版本。项目内可同时有声明式镜头与外部快照镜头。

## 5. 渲染、查看和记录

保存工程后通过独立 Blender 进程渲染；不要在单次交互调用里等待整片。每镜保留 PNG 序列，验证完整性后编码 MP4。继续任务时依赖输入摘要与文件哈希，不能仅凭“某个帧文件已存在”跳过重渲。

用 `assemble` 生成预演、`contact-sheet` 导出首/中/尾帧、`review-board` 打开逐镜审阅页。接触表只能辅助观察；运动与动作时序要查看视频或足够密集的关键帧。

检查按三层进行：

| 层次 | 关注点 | 记录 |
|---|---|---|
| 技术检查 | 帧数、fps、分辨率、文件完整性、当前输入版本 | 工具回执与日志 |
| 画面/运动检查 | 主体可见、构图、穿插/接触、姿态、速度、镜头衔接 | Codex 的观察与证据 |
| 导演判断 | 情绪、表演、叙事与用户偏好 | 用户实际给出的意见 |

示例记录（内容必须替换为真实观察）：

```bash
python -m aivw review --project projects/my-film --shot s001 --verdict fix --reviewer codex --note "人物接近门时前臂穿插；需调整第18至24帧手部位置。"
```

检查记录绑定当前视频哈希。新视频出现后原记录过期，避免把旧版通过意见沿用到新版。

## 6. 生成最终视觉

先 `seedance prepare`。逐镜交接包含预演视频、原始时长、模型生成长度、裁切计划、角色/场景/道具参考、提示词和需要保持的约束。提示词应对应预演内容，并明确物体映射；不要同时要求参考视频不包含的相反动作。

没有 API 时，交接包可以供用户/已授权的浏览器或平台工具操作。已有 API 与生成授权时，明确镜头与 take 后提交、保存回执、查询状态、下载原片。账号、上传或人像授权没有完成时，指出具体缺项，仍完成所有离线准备。

Seedance 的时长下限与最后剪辑不同。半秒镜头可以来自较长的生成原片，最终回到原镜头的整数帧；编辑模式所需的参考补时长必须显式记录。模型版本和模式变化时查官方文档，不推定旧参数继续有效。

对生成结果再次检查人物/服装一致性、物体数量、相机运动、接触、文字和前后衔接。需要几何精确或文字准确的区域可以保留 CG/实拍层，由 Codex 继续合成。生成视频可能改变边缘和空间位置，原 CG 遮罩不能默认与新像素完全吻合。

## 7. 回到剪辑并交付

保留每个 take 的未经改写原片。用 `conform` 明确选择起始时间，裁到源镜头的帧数并统一fps/尺寸，再 `assemble-final` 输出按分镜顺序的直切初剪。画面数量、顺序、总帧数都应与当前项目一致。

直切初剪是后期起点。根据项目继续做对白、环境声、音乐、字幕、调色和片头片尾；音画校准以实际项目素材为准。没有提供或生成的声音不能报告成已完成。

交付包括工程、逐镜视频、预演/初剪、参考素材映射、检查记录、生成任务回执及尚未解决的问题。大文件保存在项目目录或用户指定的素材存储；公共仓库仅保留通用代码与已授权公开的演示。

## 8. 中断恢复与扩展

先读 `status` 和上次日志，判断哪一阶段过期。分镜/布局更新后重做依赖它的工程与渲染；纯提示词变更使用新生成 take。API `unknown` 先在平台核对任务，再接回 task ID，不能自动重发 POST。

新供应商在独立模块中实现 prepare、submit、poll、download 及参数校验，保留同样的素材哈希、任务状态与原片。新项目只更换项目数据；新几何/动画能力扩展 Blender 构建器或通过 MCP 快照使用，不将具体故事写入引擎。
